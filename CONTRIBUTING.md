# Contributing to Synch

Thanks for your interest in Synch. Bug reports, fixes, documentation, ideas,
and pull requests are all welcome.

There is no strict contribution format. Follow the conventions that already
exist in the part of the repository you are changing, and explain enough
context for someone else to understand the change.

## Issues or pull requests?

For small, well-understood changes—such as fixing a bug, correcting a typo, or
making a focused improvement—feel free to open a pull request directly.

For new features or changes that could significantly affect the user
experience, API, authentication, encryption, or sync behavior, opening an
issue first is usually the better choice. It gives us a chance to discuss the
problem, the desired behavior, and the general direction before you spend time
implementing something that may not fit the project.

This is a preference, not a gate. If you already have a feature implemented,
you are welcome to open a pull request directly. It will be reviewed in good
faith, and we can discuss adjustments or alternatives as part of the review.

If you are unsure, open an issue or a draft pull request—either is a good way
to start a conversation.

Changes involving encryption, authentication, vault files, or sync behavior
deserve extra care. Please avoid including real vault contents, credentials,
tokens, or other sensitive information in issues and pull requests.

## Pull requests

There is no required PR template. A useful description usually covers:

- what changed and why;
- how the change was tested; and
- anything that may need special review or follow-up.

Small, focused pull requests are easier to review, but unfinished work and
drafts are welcome when sharing an approach or getting early feedback.

Thanks for helping make Synch better.
